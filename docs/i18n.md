# Languages — shipping scifi-theme in more than one

**You don't have to.** English-only is a completely normal thing to publish, nothing in `vvd save`,
`vvd publish`, or Workshop review will ever hold it against you, and no badge marks it "incomplete".

But the app *around* your app already speaks 19 languages. A monolingual app is the odd one
out in its own window — and adding a second language is about ten minutes.

## Where the words live

```
scifi-theme/
  vvd.json          → "locales": { "default": "en" }
  src/
    locales/
      en.json       ← the default: the catalog everything else falls back to
      fr.json       ← add a file, add a language. That is the whole declaration.
    app.tsx
```

**The filesystem is the declaration.** `vvd save` scans `src/locales/`, and the manifest it uploads
says `{ "default": "en", "supported": ["en", "fr"] }` — derived, never hand-maintained. The messages
themselves ride the *bundle* (the bundler inlines the JSON import), so they travel with your
app wherever it is installed. Nothing is stored in a table; nothing needs a migration.

## Using them

```tsx
import { createTranslator, resolveHostLocale, useHostLocale } from "@vvd/sdk"

import en from "@/locales/en.json"
import fr from "@/locales/fr.json"

const CATALOGS = { en, fr }

function useT() {
  const { locale } = useHostLocale()          // the reader's language, from the host
  return useMemo(
    () => createTranslator(resolveHostLocale({ locale, catalogs: CATALOGS, defaultLocale: "en" })),
    [locale],
  )
}
```

Then, in any component:

```tsx
const t = useT()

t("board.add")                    // "Add a note"
t("greeting", { name })           // "Bonjour, {name}"  → placeholders by NAME
t.plural("board.count", n)        // Intl.PluralRules picks the form
t.date(note.at)                   // Intl.DateTimeFormat, in the reader's language
t.number(1234.5)                  // 1,234.5 · 1 234,5 · …
```

The host decides *which* language; your catalogs decide *what you say* in it. When the reader
switches, `useHostLocale` re-publishes and your subtree re-renders **in place** — no remount, so
scifi-theme keeps its scroll position, its open panel, and its unsaved input.

## The fallback chain — it never breaks, and never shows a blank

```
what the reader asked for  →  the base language (ja-JP → ja)  →  your default  →  the key itself
```

Every rung is per-KEY, so a half-translated catalog is a *working* catalog: the keys you have
translated show in French, the ones you haven't fall back to English, and nothing throws. Ship at
any point on the way.

## Adding a language

```bash
vvd locales add fr     # writes src/locales/fr.json — every key from en.json, values blank
vvd locales check      # what's still untranslated, per language (a warning, never a failure)
```

Then import the new file into `CATALOGS` and `vvd run` — catalog edits hot-reload like any other
`src/` change.

## The traps that make a "translated" app still wrong

- **Never build a sentence out of pieces.** `t("created") + " " + name` puts the words in English
  order in every language. One phrase = one key, with placeholders: `t("created", { name })`.
- **Never suffix an "s".** `${n} note${n === 1 ? "" : "s"}` has no equivalent in most languages —
  some have three plural forms, some have none. Use `t.plural`, and give the catalog an exact-count
  form (`"0": "no notes yet"`) for the empty case.
- **Never hand-format a date or a number.** `t.date` / `t.number` are `Intl` — they know that
  1.234,5 and 2026/08/03 are the right answers somewhere.
- **Keep layout logical, not left-handed.** `margin-inline-start` over `margin-left`, `text-align:
  start` over `left` — that is all it takes for Arabic and Hebrew to lay out correctly.
- **User content is NOT UI text.** A world's cards, a note's body, your app's shared headline: those
  are the author's own words, in the language they chose. Translating them would rewrite someone's
  world. Only your app's chrome belongs in `src/locales/`.

## The checklist

- [ ] Every user-visible string in src/app.tsx comes from `t(...)` — none are typed inline.
- [ ] Counts use `t.plural`; dates and numbers use `t.date` / `t.number`.
- [ ] No sentence is assembled by concatenation.
- [ ] Nothing durable (document state, seed content) is localized.
- [ ] `vvd locales check` is clean — or you have read it and decided to ship anyway, which is fine.
